# IS1200 Processor Lab

<!-- impeccable:product-schema 1 -->

## Platform
web

## Users
KTH IS1200 Lab 4 students preparing their processor circuits and individual oral examination, especially on laptops and iPads.

## Product Purpose
An interactive environment in which students perform instruction decoding, control decisions, combinational calculations, and rising-edge updates themselves.

## Positioning
One shared processor model drives an editable visual datapath, component experiments, generated exercises, assembly encoding, and program traces.

## Operating Context
Local independent study alongside Logisim and the supplied Lab 4 PDF, Lecture 9 slides, and improved RISC-V reference sheet. The user's detailed pasted request is the confirmed product brief.

## Capabilities and Constraints
React, TypeScript, Vite; static GitHub Pages delivery; no backend, API keys, or cloud database. Lab mode uses add, addi, beq, x0–x7, a word-addressed ROM and an 8-bit byte-addressed PC. Lecture extensions must be explicitly separated. All processor semantics are shared. Progress lives locally. The public deployment target is liltaket/is1200-processor-lab, with GitHub Pages at https://liltaket.github.io/is1200-processor-lab/.

## Brand Commitments
Dark only; calm, clean, modern, restrained motion; clear distinctions between data, control, and sequential state. Technical diagrams are central to the experience. No neon overload or distracting gamification.

## Evidence on Hand
Downloads/lab4-processor-design.pdf (12 pages, 2026), lecture9.pdf (43 pages), riscv-instruction-sheet_improved.pdf (1 page). No course factorial implementation or test.S supplied; authored demonstrations must be labeled accordingly. The requested (1) filename was not found; the available Lab 4 file is used transparently.

## Product Principles
- Reason through the hardware; explain why every answer is correct.
- Keep encoded instruction fields distinct from generated control signals.
- Show combinational calculations separately from clocked state updates.
- Prioritize working, coherent learning modes over feature count.
- Preserve course scope and identify authored examples.

## Accessibility & Inclusion
Keyboard-friendly controls, labeled inputs, readable dark contrast, reduced-motion support, responsive laptop/tablet/mobile layouts.
